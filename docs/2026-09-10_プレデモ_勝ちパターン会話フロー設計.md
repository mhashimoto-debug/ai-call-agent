# 9/10 プレデモ用 勝ちパターン会話フロー設計案 v1.0

対象: BPSR 企業型DC アポイント獲得 AI エージェント
作成日: 2026-09-08 ／ 想定デモ日: 2026-09-10
根拠データ: アポ獲得15件・NG20件の文字起こし（`BPSR_AIスクリプト素材シート`）＋録音15本（計2時間14分）

> 本書に登場する企業名・氏名・連絡先はすべて**架空のプレースホルダ**です。実データの個人情報は含めていません。

---

## 0. デモのゴール

**「受付で切られていた層・断りとして処理していた層から、条件の揃ったアポを1本完走させる」**ところまでを見せる。

プレデモで証明したいのは会話の流暢さではなく、次の3点。

| # | 証明すること | 見せ方 |
|---|---|---|
| G1 | 最頻出の断りを「終話」ではなく「質問」に変換できる | 「保険でやってる」から会話を継続させる |
| G2 | 現場でばらついている**ヒアリング7項目を100%取り切れる** | 実データでは社保人数67%・カレンダー登録依頼53%しか取れていない |
| G3 | 禁止ワードを踏まない | 実データでは獲得済み4件が断定表現に抵触 |

G2 が本命。人間のトップ担当より上手く喋る必要はなく、**抜け漏れゼロで毎回同じ品質**が AI の価値提案です。

## 1. 設計の根拠（分析から確定した4つの判断）

| 判断 | 根拠 |
|---|---|
| **D1: 「制度ないので」「保険でやってる」を勝ち筋の入口に置く** | 「導入済み」約40件が最多の断り。うち機能したのは「足りているか」を問う質問のみ。「退職金制度ない」は最も見込みが高いのに全件終話しており、取りこぼし優先度が最高 |
| **D2: クローズは「仮押さえ」で取る** | 15件中もっとも綺麗に完走した No.7 の決定打が「一応仮押さえだけでもさせていただきましょうか」。「忙しい」に対し**内容ではなく時間の約束**に切り替えた瞬間に通っている |
| **D3: 法改正フックは差別化の直後に1回だけ置く** | 15件中8件で使用され、単独で関心を引いた例が複数。ただし冒頭に置くと「営業電話」と判定されるため、相手が現状を話した後に限定 |
| **D4: ヒアリングは日程確定「後」に、許可を取ってから入る** | 成功例は全件この順序。「貴重なお時間をいただきますので、御社様に合ったご提案をさせていただくために」という前置きで拒否ゼロ |

## 2. デモシナリオの前提

| 項目 | 設定 |
|---|---|
| リスト種別 | ハローワーク求人リスト（新規・接点なし） |
| 架空企業 | 株式会社サンプル工業（従業員12名・役員2名） |
| 応対者① | 受付事務（取次判断者） |
| 応対者② | 代表 中村様（50代・退職金は**保険で対応済み**・企業型DCは未認知） |
| 想定尺 | **6分30秒〜7分**（実データの中央値 約10分より短く、冗長な言い直しを排除した想定） |
| ゴール | 9/17（水）14:00 の Zoom 商談確定＋ヒアリング7項目取得 |

**なぜ「保険でやってる」設定か**: 最頻出の断り（約40件）でありながら、実データでは唯一「充足度を問う質問」だけが機能した領域。ここを取れることを見せるのが最もインパクトが大きく、かつ再現性の説明がしやすいため。

## 4. フェーズ別 詳細設計

各フェーズは **目標 / 発話 / 遷移条件 / 失敗時** で定義。`【必】` は必ず発話、`【条】` は条件成立時のみ。

### P0 受付突破（目標: 30秒以内に代表へ取次）

【必】「お忙しいところ恐れ入ります。一般社団法人企業型確定拠出年金相談センターの◯◯と申します。**退職金準備に関する件で、代表の中村様にお繋ぎいただけますでしょうか？**」

- 設計意図: 用件を**先に・短く**言う。実データでも通った受付は例外なくこの型。
- 【条】用件を問われたら → 「代表の中村様ご自身の退職金のご準備に関する件です。**初めに1点だけ確認**なのですが、御社では役員様の退職金のご準備や、社員様向けの積立制度は何かされていますか？」
  - **受付にも巻き込み質問を投げる**のが要点。受付を「取次判断者」から「情報提供者」に変えると切られにくい。
- 【条】「営業電話はお断りと言われております」 → P0-X へ

**遷移**: 取次発生 → P1
**失敗時（P0-X 撤退時の痕跡残し）**:
「かしこまりました。**厚生労働省が管轄する制度**のご案内ですので、もし社内でお話が出ました際はご伝言だけいただけますと幸いです。失礼いたします。」
→ 実データではこの層（約30件）に切り返しがほぼゼロ。**即終話せず必ず1文残す**ことを標準化する。

---

### P1 代表接続・巻き込み質問（目標: 相手に現状を喋らせる）

【必】「お忙しいところありがとうございます。一般社団法人企業型確定拠出年金相談センターの◯◯と申します。突然のお電話失礼いたします。」
【必】「**厚生労働省が管轄する退職金制度、企業型確定拠出年金についてのご案内です。制度が厚労省の管轄で、私どもはその導入を支援している民間の事業者になります。**」
【必】「初めに1点だけ確認なのですが、御社では役員様の退職金のご準備や、社員様向けの積立制度は何かされていますか？」

> **⚠ 立場の切り分けは必須**。NGデータでは「厚労省管轄」だけを名乗った結果、相手が公的機関と誤認して「お国がやるなら手数料かからんだろう」と最後まで噛み合わず終話した例がある。**管轄と自社の立場を必ず同じ一息で言い切る。**

**遷移**: 何らかの回答 → P2

---

### P2 断り受け止め → 充足度質問（★最重要）

相手「うち、退職金は保険でやってるので」

【必】受け止め: 「保険でご準備されているんですね、ありがとうございます。」
【必】充足度質問: 「**ちなみにそちらは、中村様ご自身の退職金のご準備としても十分に活用できていらっしゃいますか？**」

- 設計意図: **「制度があるか」ではなく「足りているか」を聞く。** 実データで「導入済み」約40件のうち、会話が継続したのはこの型のみ。
- 分岐: 「制度ないんです」と返ってきた場合 → **断りではなくホットサインとして扱う**（下記 ガードレール R1）

**遷移**: 相手が現状の不足・不明を口にする → P3

---

### P3 差別化（目標: 「別枠の話」だと理解させる）

【必】「実は保険と企業年金制度は別のもので、こちらは **代表や役員の方ご自身が、全額会社の経費（損金）で** 将来の資産形成ができる制度です。」
【必】「社員さんについては額面から積み立てる形になりますので、**社会保険料が下がる場合があり**、手取りを増やしながら将来の資産が作れます。」
【必】「つまり **コストを増やさずに待遇を良くできる**、というのが一番のメリットです。」

> **⚠ 禁止ワード注意**: 「社会保険料の削減になります」は断定表現。実データでは獲得済み4件が抵触している。**必ず「下がる場合があります」**。

- 【条】「中退共に入っている」 → 「中退共は**従業員様のみ**が対象ですので、中村様ご自身の退職金は別枠になります」
- 【条】「iDeCo/小規模企業共済をやっている」 → 「**併用いただけます**。iDeCo は個人のお財布から、企業型DCは会社の経費から、という違いです」

**遷移**: 理解の反応 → P4

---

### P4 法改正フック（1回のみ・ここでしか使わない）

【必】「さらに **2026年12月に法改正が予定**されておりまして、経費で積み立てできる上限が **月55,000円から62,000円に上がる予定**です。始めるタイミングで損得が変わるところなので、事前に確認だけされる企業様が増えている状況です。」

> ⚠ 施行時期・上限額は**デモ前に必ず一次情報で再確認**（②シートにも「要確認」の注記あり）。数字を外すとデモ後の信頼を失う。

**遷移** → P5

---

### P5 低ハードル打診（目標: 意思決定ではなく情報取得として提示）

【必】「実際どれくらいメリットが出るかは人数や給与によって変わりますので、**今すぐご導入くださいというお話では全くございません**。」
【必】「**情報収集の一環として30分ほど**、Zoom で御社の場合の費用対効果とシミュレーション、今回の法改正の影響だけ簡単にお伝えできればと思うのですが、ご都合いかがでしょうか？」

**遷移**: 即OK → P7 ／ 保留・多忙・要相談 → P6

---

### P6 仮押さえクローズ（★決定打・実データ No.7 の勝因）

相手「今週バタバタしてて…」「みんなと相談してからになる」

【必】反論を段取りに変換: 「**一度お話を聞いていただいて、その後に社内で活用価値があるかご相談いただく、という段取りが一番かと思います。**」
【必】仮押さえ: 「**一応、仮押さえだけでもさせていただきましょうか。**」
【必】リスク解除: 「ご都合が悪くなりましたら前日のお電話で変更いただけますので。」

> 設計原則: **忙しい相手に内容を被せない。** 実データでは説明を被せた架電は10件以上すべて切られ、時間の話に切り替えた架電のみが通っている。P6 では新しい制度説明を一切足さない。

**遷移** → P7

---

### P7 日程2択クローズ（目標: 開いた質問を使わない）

【必】「来週でしたら、**午前と午後どちらがよろしいですか？**」→「では **17日（水）14時から30分**でいかがでしょうか？」

- 設計原則: 「いつがよろしいですか？」は禁止。**必ず2択→1点確定**の順。
- 【条】「Zoom って何？」 → 「スマートフォンでも参加できます。メールでお送りする URL をタップいただくだけです」（実データで2件同じ質問あり・想定内）
- 【条】「そちら遠いですよ」 → 「オンラインですので移動は不要です」

**遷移**: 日時確定 → P8

---

### P8 ヒアリング7項目（★G2 の本体・全項目必須）

【必】許可取得: 「では貴重なお時間をいただきますので、**御社様に合ったご提案をさせていただくために**何点かご質問させてください。今お時間よろしいでしょうか？」

| # | 項目 | 質問文 | 実データ実施率 |
|---|---|---|---|
| H1 | iDeCo・投資の有無 | 現在 iDeCo やその他の投資はされていますか？（有→月額も） | 80% |
| H2 | 既存の退職金制度 | 御社で退職金制度は何かご導入されていますか？ | 87% |
| H3 | 代表年齢 | 差し支えなければ中村様のご年齢を伺えますか？ | 87% |
| H4 | 役員人数・年齢 | 役員様は中村様含め何名でいらっしゃいますか？（→各年齢） | 73% |
| H5 | **社保加入人数** | 社会保険にご加入の人数は何名くらいですか？ | **67% ⚠** |
| H6 | 決裁権 | こういった制度をご導入される際は中村様のご判断で決められますか？ | 87% |
| H7 | 決算月 | 御社の決算月はいつになりますでしょうか？ | 80% |

> **H4・H5 が最大の穴**。シミュレーション精度に直結するため、**AI側では未取得なら次フェーズに進めないバリデーションを実装**する。

【必】メールアドレス取得（復唱確認込み）
【必】前日確認の連絡先・希望時間帯

**遷移**: 7項目＋連絡先が揃う → P9

---

### P9 締め（目標: 無断キャンセルを防ぐ）

【必】担当者予告: 「当日は弊社グループの**社会保険労務士法人ビジネスパートナー**の有資格のプランナーからお話しさせていただきます。会社概要と Zoom の URL をメールでお送りします。」
【必】**カレンダー登録依頼**: 「担当の予定の兼ね合いで、もし日程変更になりますと次回のご案内がかなり先になる可能性がございます。お手数ですが **9月17日14時で、一旦カレンダーにご予定だけ入れておいて**いただけますと助かります。」
【必】前日連絡の予告 → 「当日はどうぞよろしくお願いいたします。」

> **カレンダー登録依頼は実データで53%しか実施されていない**（スクリプトでは「★必ず」指定）。ここを100%にできることが、そのまま商談実施率の改善として提示できる。

## 5. ガードレール（勝ち筋を守る分岐ルール）

| ID | トリガー | 挙動 |
|---|---|---|
| **R1** | 「退職金制度はない」「これから」 | **断り判定を禁止**。「これから作られる前提で、役員様1名からでもご導入いただけます」で P3 へ。②シートで改善優先度**最高**と特定された取りこぼし |
| **R2** | 「忙しい」「時間がない」 | 制度説明を**被せない**。「本日中でお時間いただける頃はございませんか？」または P6 の仮押さえのみ |
| **R3** | 「税理士・社労士に任せている」 | 否定しない。「先生にご相談いただくための**判断材料**をお渡しするところまでが私どもの担当です」。※「税理士は詳しくない」は反発を招くため禁止 |
| **R4** | 「資料だけ送って」 | 送付で終わらせない。**送付手段の選択肢（SMS/メール/封書）＋再架電日の確定**をセットで取る |
| **R5** | 相手が公的機関と誤認 | 即座に「制度は厚労省管轄、**私どもは民間の導入支援事業者**です」を再提示 |
| **R6** | 断定表現の生成 | 出力前フィルタで機械的にブロック（§6） |
| **R7** | 応対者が代表でない／決裁権なし | ヒアリングを続けず、**次回接触条件**（出社日・繋がりやすい時間帯）の確定に切り替える |

## 6. 禁止ワード・言い換え表（出力前フィルタに実装）

| 禁止 | 言い換え | 理由 |
|---|---|---|
| 社会保険料が下がります／削減になります | 社会保険料が**下がる場合があります** | 給与額・等級により下がらない場合がある |
| 元本保証／必ず増えます | 運用商品によって結果は変動します | 元本を下回る可能性がある |
| 絶対もうかります／必ず10%で運用 | （使用禁止・代替なし） | 断定不可 |
| 岡三証券 / 三井住友信託銀行 | （固有名を出さない） | 提携条件上の制約 |
| 「厚労省管轄です」単独 | 「制度は厚労省管轄、当社は民間の導入支援事業者」 | 公的機関との誤認防止 |

## 7. アポ成立判定（Definition of Done）

デモの成否は主観ではなく、下記が**全部○になったか**で判定する。

- [ ] 商談日時が確定している（日・時刻とも）
- [ ] Zoom 実施と所要30分に同意を得ている
- [ ] H1〜H7 の7項目すべて取得
- [ ] メールアドレス取得＋**復唱確認済み**
- [ ] 前日確認の連絡先と希望時間帯を取得
- [ ] **カレンダー登録を依頼した**
- [ ] 禁止ワードの発話ゼロ

## 8. デモ運用手順（9/10）

1. **客役の台本を先に固定する**。AI のアドリブ評価はプレデモの目的ではないため、応対者の返答は本書 §4 の想定どおりに固定して読み上げる。
2. 提示順: ①この設計フロー図 → ②実際の通話デモ → ③DoD チェックリストの充足結果。
3. **比較対象を必ず出す**: 実データの実施率（社保人数67%・カレンダー登録53%）を並べ、「人間のばらつきを AI が埋める」構図で見せる。
4. 本番前に法改正の数値（55,000→62,000円・2026年12月）を一次情報で再確認。

## 9. 意図的にスコープ外にしたもの

プレデモを1本の勝ち筋に絞るため、以下は **v1.0 では実装しない**（次フェーズ）。

- 受付の強固なブロック（「営業電話は全てお断り」約30件）への突破ロジック — 型が未確立で、実データにも成功例がない
- 再架電・既存接点先の日程再設定フロー（獲得15件中4件がこれ。新規獲得とは別設計が必要）
- 複数制度を併用中の上級者への詳細比較（実データ最長15分49秒。デモ尺に収まらない）
- 「資料送付のみ」からのナーチャリング

## 10. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 法改正の数値が誤り | デモ後の信頼失墜 | 9/10 前に一次情報で確認（②シートにも要確認注記あり） |
| 断定表現の生成 | コンプライアンス違反 | §6 を出力前フィルタとして実装。生成後チェックではなく生成前制約 |
| 公的機関との誤認 | クレーム化（NGデータに実例あり） | P1 の立場切り分けを必須発話に固定 |
| 学習素材の汚染 | 違反表現の再生産 | **獲得済み4件（No.7/8/11/15）の断定表現を修正してから学習投入** |
| 文字起こしの固有名詞誤認識 | 自社名を正しく名乗れない | 「確定期出/確定給付/入れ子」等の誤変換を辞書修正してから投入 |

## 付録: 実データから抽出した「効いた一言」

そのまま AI の発話テンプレートに採用したフレーズ。
