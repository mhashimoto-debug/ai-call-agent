# BPSR 企業型DC アポ獲得 AI架電エージェント（プレデモ v1.0）

`docs/2026-09-10_プレデモ_勝ちパターン会話フロー設計.md` の会話設計を、そのまま実行可能にした実装です。

## 設計思想

**LLM に会話設計を任せない。** LLM が担当するのは「その場の1発話をつくること」だけで、
デモで証明したい3点（G1〜G3）はすべて決定論的なコードで担保しています。

| 証明したいこと | 実装での担保 |
|---|---|
| G1 断りを終話ではなく質問に変換する | `src/domain/guardrails.ts` — R1/R3/R4/R5 発火中は終話への遷移をコードが却下する |
| G2 ヒアリング7項目を100%取り切る | `src/domain/state.ts` — H1〜H7・メール復唱・前日連絡先が揃うまで P8→P9 の遷移を機械的にブロック |
| G3 禁止ワードを踏まない | `src/domain/forbidden.ts` — 生成前制約＋出力前フィルタ。自動修正 → 再生成 → 定型文フォールバックの3段で、禁止表現は相手に届かない |

## 構成

  web/             Web フロントエンド（描画と再生制御のみ。会話ロジックは持たない）

## 実行

```bash
npm install

# 認証（いずれか）

npm run demo      # 台本モード。Enter で1ターンずつ進む（本番のデモはこれ）

npm test          # 56 件。禁止ワード・遷移ブロック・DoD・モック再生・読み上げ正規化・対話判定
npm run typecheck
```

```bash

```

会話ログの横に、フェーズ進行・ヒアリング7項目・DoD チェックリスト・人間の実施率との比較・
ガードレール発火が**同時にリアルタイムで埋まっていく**画面です。
設計書 §8 の提示順（①フロー ②通話デモ ③DoD 充足結果）を1画面で見せられます。

#### 台本モード / マイクモード

ヘッダーのセレクトで切り替えます。

| モード | 相手の発話 | AI の応答 | 用途 |
|---|---|---|---|
| 台本モード（既定） | 固定台本（`customerScript.ts`） | `mockEngine` が再生 | 本番デモ。毎回同じ内容で確実に完走する |
| マイクモード | **音声認識（Web Speech API）** | `dialogEngine` がルールで判定 | その場で話しかけて分岐を見せる |

**マイクモード**では「🎤 マイクで話す」を押して話しかけると、音声がテキスト化され、
そのまま対話判定エンジンに渡ります。認識中は暫定テキストが薄く表示され、
話し終わりを検出すると確定します（「■ 話し終わり」で手動確定も可）。
話し終わりはブラウザ任せにせず、無音が 1.3 秒続いた時点で判定します。「〜で」「〜ですが」「〜から」のように
続きがありそうな切れ方なら、さらに 1.2 秒待ちます（`src/web/endpoint.ts`）。文の途中の間で AI が割り込まないためです。

AI は以下の順で判定して応答し、**フェーズとガードレールの分岐が画面に反映されます**。

1. 取次ぎの保留（「少々お待ちください」「代表に代わります」）は喋らずに待つ。
   担当者が出たら（「お電話代わりました」「お待たせしました」）いきなり質問に入らず、
   名乗り直し（`p1_handoff_reintro.mp3`）→ 法改正の概要 → ヒアリングの順に進む
2. ガードレール判定（R5 誤認 → R7 決裁者不在 → R1 制度なし → R3 専門家 → R4 資料 → R2 多忙）
3. フェーズ別の意図判定（肯定／否定／質問／条件分岐）
4. P8 では「今どの項目を聞いているか」を保持し、その文脈で回答を解釈。
   聞き取れなければ次に進まず聞き直す

応答ごとに「判定: ◯◯」という内部メモが出るので、**なぜそう返したかをその場で説明できます**。

> ルールベースであり LLM は使いません（オフライン動作のため）。
> API キーを設定すれば `CallAgent.respond()` に差し替えられます。
> 音声認識は Chrome / Edge / Safari のみ対応（Firefox は非対応。起動時に判定して表示します）。

#### 操作

- 「▶ 次のターン」で1ターンずつ、「⏩ 自動再生」で通しで再生（台本モード）
- 「音声で読み上げる」を ON にすると AI 側の発話を Web Speech API で読み上げます
  - 日本語ボイスは**自然に聞こえる順に自動で並べ替え**、先頭（推奨）を既定にします。
    隣のセレクトで手動変更もできます（Edge の Nanami/Keita Natural が最も自然です）
  - 読み上げは発話の終了を待ってから次に進むため、**ログと音声がずれません**
  - 読み上げ用のテキスト正規化は `src/web/speech.ts`（金額・曜日・英略語・メールの記号読み）
- 再生中に上へスクロールすると追従が止まり、右下の「⤓ 最新の発話に追従」で復帰します
- ビルド済みの `web/app.js` をコミットしてあるため、サーバを立てずに
  `web/index.html` を直接ブラウザで開いても動きます（デモ当日の保険）

#### 架電履歴（ダッシュボード）

ヘッダー右上の「📋 架電履歴」で切り替えます。通話が終わる（アポ獲得・終話・担当者への引き継ぎ・不在・断り）と、
日時・企業名・ステータス・通話時間が自動で一覧に追加されます。行をクリックすると詳細画面が開き、
アポ成立チェックの判定、ヒアリング7項目と連絡先、タイムスタンプ付きの通話全文ログを確認できます。

- 保存先はブラウザの localStorage（キー `ai-call-agent:call-history:v1`、最大200件）。サーバーには送りません
- 保存はブラウザ・端末ごと。別のブラウザや別の PC とは共有されず、プライベートブラウズでは保存されないことがあります
- 途中で「リセット」やタイプ切替をした通話は、終了していないため記録しません
- 記録の組み立てと保存は `src/web/history.ts`、表示は `src/web/historyView.ts`

### GitHub Pages で公開する

`npm run build:web` は web/ をビルドしたあと、`web/index.html` と `web/app.js` を
**リポジトリ直下にもコピー**します（`npm run copy:root` 単体でも実行可）。
Pages を **main ブランチの `/ (root)`** で公開すれば、
`https://<user>.github.io/ai-call-agent/` がそのままデモ画面になり、404 になりません。

直下の `index.html` / `app.js` は生成物です。**編集は必ず `web/` 側**に行い、
`npm run build:web` で反映してください（`.nojekyll` も同スクリプトが生成します）。

**ブラウザ音声デモへの拡張点**は `src/web/main.ts` の2箇所だけです。

| 拡張 | 差し替える場所 |
|---|---|
| ~~相手の音声入力~~ | **実装済み**（`src/web/mic.ts` + マイクモード） |
| AI 応答を実 LLM に | `DialogEngine.respond()` → `CallAgent.respond()`（API キーが必要） |

`domain/` のフロー・ガードレール・DoD 判定はどちらの拡張でもそのまま再利用されます。

実行するたび `reports/call-<日時>.md` に通話レポート（DoD チェックリスト・会話ログ・
遮断した禁止表現・人間の実施率との比較）を書き出します。デモの提示順 ③ にそのまま使えます。

## モデル設定

`claude-opus-5` / adaptive thinking / effort=medium。環境変数で変更できます。

```bash
CALL_AGENT_MODEL=claude-opus-5
CALL_AGENT_EFFORT=medium   # low | medium | high | xhigh | max
```

会話設計（system プロンプト）は毎ターン不変にして prompt cache に載せ、
変化する状態は messages 末尾の system メッセージで渡しています。

## v1.0 のスコープ外（設計書 §9）

受付の強固なブロック突破、再架電・既存接点先の日程再設定、複数制度併用者への詳細比較、
資料送付のみからのナーチャリングは実装していません。
電話回線（Twilio 等）は次フェーズです。ブラウザ音声は読み上げ（TTS）・音声認識（STT）とも実装済みで、
マイクに話しかけて AI と対話できます。

## 現在の動作モード

**API キーなしのオフライン・モック動作を v1.0 の確定形とします。**
発話は設計書の定型文・台本の指定台詞から生成し、Claude API は呼びません。
ただし**フェーズ遷移の検証・ヒアリング充足判定・DoD 判定・ガードレールは本番と同じコードを通る**ため、
デモで証明したい G1〜G3 はモックモードでもそのまま成立します。

実 LLM 応答（`npm run demo`）は実装済み・型検査済み・スタブでの単体テスト済みですが、
**実 API での応答品質は未検証**です。API キーを設定すれば同じ台本でそのまま動きます。
